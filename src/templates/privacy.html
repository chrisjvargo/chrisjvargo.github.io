1. Overview & Scope

This Privacy Policy explains how KidAdLens (hosted at {{ site_url }}/kidadlens) and the accompanying informational pages on chrisjvargo.com access, use, store, protect, and delete information, including data accessed through Google OAuth 2.0 and Google APIs. KidAdLens is an academic research tool developed and operated by Dr. Chris J. Vargo for scholarly analysis of mobile advertising transparency and child safety.

2. Information Accessed & Collected

2.1 Google User Data Accessed via Google OAuth 2.0

When an authorized researcher explicitly grants consent through Google's OAuth 2.0 screen, KidAdLens requests access only to the following Google API scope:

  • https://www.googleapis.com/auth/colaboratory — used to interact with Google Colab compute resources associated with the authorizing Google account.

Through this scope, KidAdLens accesses only the minimum operational metadata required to run user-initiated compute jobs:

  • OAuth 2.0 access tokens and refresh tokens issued by Google for authenticating API requests on the user's behalf;
  • Google Colab account tier, compute-unit balance, and available GPU accelerator specifications;
  • Temporary Colab runtime identifiers, assignment endpoints, health status, and execution logs produced by KidAdLens research scripts running inside those temporary runtimes.

2.2 Data We Do NOT Access

KidAdLens does not request, access, read, or collect Gmail messages, Google Drive personal files or folders, Google Contacts, Google Calendar events, Google Photos, YouTube watch history, payment instruments, or any other Google Workspace or personal user data outside the single Google Colab API scope listed above.

2.3 Static Informational Website

The informational web pages hosted on chrisjvargo.com (including /kidadlens, /privacy, and /tos) are static HTML pages served via GitHub Pages. We do not place advertising cookies, behavioral trackers, or user login walls on these pages. GitHub Pages may collect standard HTTP server logs (such as IP address and request timestamp) in accordance with GitHub's privacy practices.

3. How We Use Google User Data

KidAdLens uses Google user data strictly and exclusively to perform the compute tasks initiated by the authorizing user:

  • Authenticating API calls to Google Colab on behalf of the authorizing researcher;
  • Verifying available compute capacity and GPU runtime options before scheduling research workloads;
  • Provisioning temporary Colab GPU runtimes, uploading research inference scripts and ad-creative analysis batches, retrieving structured evaluation outputs, and cleanly terminating runtimes upon completion;
  • Tracking compute-unit expenditure so automated research jobs stay within user-specified limits.

We explicitly commit to the following restrictions:

  • We do not sell, rent, lease, or trade Google user data to any third party.
  • We do not use Google user data for targeted advertising, personalized marketing, data brokering, or creditworthiness evaluation.
  • We do not use any data obtained through Google APIs to develop, improve, or train generalized artificial intelligence (AI) or machine learning (ML) models.

4. Google API Services User Data Policy (Limited Use)

KidAdLens's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

5. Data Sharing & Disclosure

KidAdLens does not share, disclose, or transfer Google user data or OAuth tokens to third parties. API requests are transmitted directly between the researcher's controlled execution environment and official Google API endpoints (oauth2.googleapis.com, colab.research.google.com, and colab.pa.googleapis.com). We would disclose information only if strictly required to comply with applicable law or a valid legal process.

6. Data Storage & Security

  • Encrypted in Transit: All communication between KidAdLens and Google OAuth / Google Colab services is encrypted using HTTPS/TLS.
  • Restricted Local Storage: OAuth 2.0 access and refresh tokens are stored solely on the operator's access-controlled local Linux host with strict owner-only filesystem permissions (0600). Credentials are never committed to source control, exposed in client-side browser code, or uploaded to third-party databases.
  • Ephemeral Runtimes: Provisioned Google Colab runtimes are temporary compute environments that are automatically unassigned and released when research inference batches finish or stop.

7. Data Retention, Revocation & Deletion

OAuth tokens and runtime operational state are retained locally only for as long as the authorizing researcher actively operates KidAdLens compute jobs. You remain in complete control of your Google account authorization and can revoke access or request deletion at any time:

  • Instant Revocation via Google: Visit your Google Account third-party access settings at https://myaccount.google.com/permissions, select KidAdLens, and choose Remove access.
  • Local Credential & Data Deletion: Upon revocation—or upon emailing a deletion request to christopherjvargo@gmail.com—all locally stored OAuth tokens, refresh tokens, and cached session metadata associated with your Google account are permanently deleted immediately (and no later than 24 hours after an email request is received).

8. Children's Privacy

Although KidAdLens studies advertising shown in child-directed mobile applications for academic child-safety research, KidAdLens itself is a scholarly software tool operated exclusively by adult researchers. It does not offer accounts to children and does not knowingly collect personal information from children under 13 (or the applicable age of digital consent in any jurisdiction).

9. Changes to This Privacy Policy

We may update this Privacy Policy from time to time to reflect changes in KidAdLens's technical workflow or applicable legal and platform requirements. Any updates will be published on this page with a revised effective date.
